# Архитектурное решение по кешированию
---

## 1. Анализ системы

Проведён анализ диаграммы системы и её описания. Основной пул проблем сосредоточен в системе MES, поэтому первоочередное внимание будет уделено кешированию именно этой системы. В дальнейшем целесообразно внедрить кеширование и для системы интернет-магазина, однако на начальном этапе основное внимание уделяется MES.

---

## 2. Мотивация внедрения кеширования

Внедрение кеширования позволит решить ряд проблем с производительностью системы:

- **Скорость доступа:**  
  Кеширование значительно ускоряет доступ к данным, поскольку браузеры, серверы и приложения обращаются к кешу, а не к базе данных или удалённым сервисам. Это уменьшает задержки при выполнении операций.

- **Снижение времени отклика:**  
  Использование кеша позволяет пользователям получать данные быстрее, что улучшает общий пользовательский опыт. Это особенно важно для веб-приложений, где даже незначительные задержки могут негативно сказаться на взаимодействии с системой.

- **Оптимизация нагрузки на базу данных:**  
  Кеширование снижает количество обращений к базе данных, что позволяет системе более эффективно справляться с пиковыми нагрузками и уменьшает риск отказов.

В рамках данного решения планируется включить в кеширование данные системы MES, а в дальнейшем — и данные интернет-магазина.

---

## 3. Предлагаемое решение

### Тип кеширования

Поскольку для операторов критически важна актуальная информация по заказам, будет использовано **серверное кеширование**. Сервер обладает возможностью управления актуальностью кешированных данных, что позволяет предоставлять свежую информацию и минимизировать риск устаревания данных. Кроме того, учитывая работу с 3D-моделями изделий, серверное кеширование предпочтительнее из-за допустимого объёма кешируемых данных.

### Выбор паттерна кеширования

Наиболее подходящим паттерном для рассматриваемого случая является комбинация паттернов **Refresh-Ahead / Write-Behind**. Такой подход обеспечивает:
- **Высокую согласованность:** Кеш обновляется заблаговременно для часто запрашиваемых данных, что минимизирует риск устаревания информации.
- **Высокую скорость передачи данных:** Паттерн позволяет поддерживать актуальность кеша без излишней нагрузки на базу данных.

В сравнении с альтернативными паттернами:
- **Cache-Aside:** Может оказаться менее эффективным для часто запрашиваемых данных, так как требует явного обращения к базе данных при отсутствии записи в кеше.
- **Write-Through:** Может создавать дополнительную задержку при записи данных, что нежелательно для системы с высокими требованиями к производительности.

### Стратегия инвалидации кеша

Предлагается следующая стратегия инвалидации кеша:

- **Настройка TTL:**  
  Каждая кешированная запись получает значение TTL (time-to-live). По истечении этого времени данные считаются устаревшими, и инициируется фоновое обновление кеша.

- **Обработка уведомлений об изменениях:**  
  При изменении данных в базе (операции создания, обновления или удаления) система получает уведомление и инвалидирует соответствующие кешированные записи, гарантируя актуальность отображаемой информации.
