# Архитектурное решение по логированию

---

## 1. Анализ системы и сбор логов

### События, которые необходимо логировать (уровень INFO):

- **Shop:**
  - Создание заказа (время, исполнитель, ID созданного заказа)
  - Изменение статуса заказа (ID заказа, время, исполнитель, предыдущее значение, новое значение)
  
- **CRM:**
  - Создание заказа (время, исполнитель, ID созданного заказа)
  - Изменение статуса заказа (ID заказа, время, исполнитель, предыдущее значение, новое значение)
  
- **MES:**
  - Создание заказа (время, исполнитель, ID созданного заказа)
  - Назначение заказа на исполнителя (исполнитель, время, срок выполнения)
  - Изменение статуса заказа (ID заказа, время, исполнитель, предыдущее значение, новое значение)
  
- **Уведомления (Email/SMS):**
  - Отправка уведомлений (время, получатель, связанный элемент)

Также необходимо логировать отказы системы, используя уровни **Error** и **Warn**, поскольку жизненный цикл заказа может тормозиться из-за ошибок в API или недоступности отдельных ресурсов.

---

## 2. Мотивация

Внедрение логирования в систему позволит:

- **Диагностика и устранение неисправностей:**  
  Логи помогут быстро определить причины сбоев и ошибок, снизив затраты времени на поиск и воспроизведение багов.
  
- **Безопасность и аудит:**  
  Сбор логов позволяет отслеживать подозрительную активность, проводить аудит и расследование инцидентов, что критически важно для защиты данных и соблюдения нормативных требований.
  
- **Повышение производительности:**  
  Анализ логов поможет выявить узкие места в работе системы, оптимизировать обработку запросов и сократить время отклика.
  
- **Метрики влияния:**
  - **Время реагирования на инциденты:**  
    Техническая метрика – уменьшение среднего времени реагирования на инциденты благодаря быстрому доступу к логам; бизнес-метрика – сокращение времени простоя системы.
  - **Частота ошибок и сбоев:**  
    Техническая метрика – снижение количества ошибок, выявленных в логах; бизнес-метрика – повышение уровня удовлетворенности клиентов.
  - **Производительность системы:**  
    Техническая метрика – сбор данных о времени выполнения операций для оптимизации кода; бизнес-метрика – увеличение числа успешных транзакций и улучшение качества обслуживания.

Поскольку основные жалобы пользователей и исполнителей связаны с задержками в работе MES, первоочередное внимание следует уделить улучшению логирования и трейсинга именно этой системы.

---

## 3. Предлагаемое решение

Для централизованного сбора, хранения и анализа логов предлагается использовать **ELK Stack** (Elasticsearch, Logstash, Kibana).

### Основные компоненты решения:

- **Logstash:**  
  Собирает и обрабатывает логи со всех систем (Shop, CRM, MES, уведомлений) с уровнем INFO, а также логи ошибок (Error, Warn).

- **Elasticsearch:**  
  Хранит логи в отдельном индексе для каждой системы или в виде разделённых файлов логов (например, один файл в сутки). Это позволит эффективно осуществлять поиск и анализ данных.

- **Kibana:**  
  Обеспечивает визуализацию логов через дашборды, что помогает оперативно анализировать события и выявлять аномалии.

### Политика безопасности логов:

- **Доступ:**  
  Доступ к логам имеют только технические специалисты с правами администратора (DevOps, Ведущий разработчик).  
- **Шифрование:**  
  Логи передаются по защищённым каналам (SSL/TLS) и хранятся в зашифрованном виде для защиты от несанкционированного доступа.
- **Аудит доступа:**  
  Все попытки доступа к логам логируются для последующего аудита.

### Политика хранения логов:

- Логи будут храниться в отдельном индексе или в виде файлов, разделённых по системам и датам (например, один файл в сутки).
- На начальном этапе настройка автоматического удаления логов старше шести месяцев с последующим сокращением срока хранения до трех месяцев после стабилизации работы системы.

---

## 4. Мероприятия по превращению системы сбора логов в систему анализа логов

Для обеспечения не только сбора, но и анализа логов, планируются следующие мероприятия:

- **Мониторинг и оповещение:**  
  Использование инструментов мониторинга и оповещения (например, Prometheus, Grafana) для отслеживания критических событий, выявленных на основе логов.
  
- **Автоматизация анализа:**  
  Настройка регулярных отчётов и дашбордов для анализа ключевых метрик, полученных из логов, с целью оперативного принятия мер по оптимизации системы.
  
- **Интеграция с процессами поддержки:**  
  Организация автоматизированных триггеров для уведомления специалистов о выявленных проблемах (например, увеличение количества ошибок, задержки в обработке заказов).
